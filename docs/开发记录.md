## 2026-11-03 M1：PDF 页级混合路由 + OCR 引擎抽象

### 交付

- `src/ocr/`（feature `ocr`）：`OcrEngine` trait（注入式：rumi 采用/测试 mock/
  其它引擎均不改 pdf 后端）+ `RecognizedLine`（四点框保真，`axis_rect()` 转
  IR 包围盒）；`ocr-oar` feature 提供 `OarOcrEngine::shared()`（全局唯一
  `Arc<dyn OcrEngine>`，懒加载，pp-ocrv6 small）。

  Rust）：`OcrMode{Auto,On,Off}` + `PdfOptions{mode,dpi,engine}`；一次
  `ScanStrategy::Full` 分类 → 文字层直提（TextLayer/Pt/confidence=None）→
  扫描页连续区间 pdftoppm 渲染 + 引擎识别（Ocr/Px{dpi}/confidence）。
  Off 模式扫描页不出块、warnings 记页号。坐标系契约见模块头。
- `plugin.rs`：`RawTextItem{source,confidence}`、`RawPage.coord_units` 透传。
- 顶层 `docforge::parse(path)`（默认装配：文本族 + pdf + ocr 引擎自动接线）。
- `examples/pdf_dump.rs`：公共 API 行集 dump（对表辅助）。

### 与 rumi 对表（验收 §7.5）结论

- **语义对表**：`text_line_to_item` 与 rumi `text_line_to_ocr` 逐行语义一致
  （同一 pdf-inspector API、同样的空文本/Image 过滤、同样的 item 框并集、
  同一坐标系契约）；分类（Full 逐页）与区间合并渲染同构。
- **二进制级对表受阻（环境）**：本机 Debian 12 glibc 2.36 缺 `__isoc23_*`
  符号，ort 2.0.0-rc.13 的 onnxruntime 静态库（glibc≥2.38 编译）链接不过
  ——rumi 浅克隆同样挂（example 与 lib test 均无法链接），非 docforge 代码
  问题；换系统 cc 链接器无效。**待 rumi 侧可用环境（或 ort load-dynamic）
  补跑同文件对表**。两侧各自的同款样例 ≥0.98 断言：docforge 侧绿，rumi 侧
  以其仓库测试为准。
- OCR 端到端（#[ignore] 用例）本机无法跑：无 pdftoppm（poppler-utils）、
  无 ~/.oar 模型缓存 + 上述链接限制。三条环境要求已写入用例 ignore 注释。

## 2026-11-03 M0：工程骨架 + core 吸收 + IR 定稿

### Q3 核实：pdf-inspector 依赖面（M0 交付物，三问三答）

方法：临时壳 crate（/tmp/q3probe）`cargo add pdf-inspector@1` 实拉 1.25.2，
`cargo tree --edges normal` + `cargo metadata` 查 feature 结构。

1. **firecrawl-pdfium / ort / pyo3 是否 default 依赖？**
   **否**。`default = []`（空），全部重依赖走 feature 门控：
   `render-pdfium`→firecrawl-pdfium；`ocr-oar`→oar-ocr+ort+image；
   `ocr` = render-pdfium + ocr-oar + model-download；`pyo3`/`python` = Python 绑定。
2. **纯文字层提取（分类 + group_into_lines）能否不拉 ort/pyo3？**
   **能**。default 面仅 lopdf / env_logger / log / jiff / include_dir 等纯 Rust
   轻依赖，`detect_pdf_type_with_config` 与文字层提取都在 default 面内。
3. **降级方案是否触发？** **不触发**。docforge M1 采
   `pdf-inspector = { version = "1", default-features = false }` + 自有 feature
   `ocr`（门控 oar-ocr）；渲染走系统 pdftoppm（不拉 firecrawl-pdfium）。
   修正：docparse-plan §2.3"底层依赖 firecrawl-pdfium + ort（+pyo3）"为过时
   描述（那是 `ocr`/`python` feature 的传递面），§14 风险 2 解除。
